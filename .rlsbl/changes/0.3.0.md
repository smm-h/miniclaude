## 0.3.0

Starting a fresh session has a name of its own, and every flag says whether it is required.

<details>
<summary>Context</summary>

strictcli 0.41 makes presence a declaration rather than something the framework
infers, and it replaces the mutex group with a member-spelled choice flag.
Adopting both changed two things about `miniclaude repl`.

Which session the REPL runs was previously two independent flags plus an
unnamed third state: `--resume <id>`, `--continue-session`, and whatever
happened when neither was passed. The handler checked that pair by hand, so a
third alternative would have meant a third branch in that check. It is now one
selection over three named members, `--new-session` included. Every command
line that worked before works unchanged -- `--no-continue-session` included --
and passing two members is the framework's refusal.

The empty-string sentinel is gone from both commands. `--cwd` and `--seed`
declared `default=""` and their handlers read absence back out of the empty
string, so `miniclaude mock --seed ""` quietly took a random seed where it
should have refused. Absence is absence now, and the empty string is a value
that does not parse.

</details>

### Breaking

- **`--help` states each flag's presence, and `--permission-mode` explains its six modes.** Every flag now renders `[required]` or `[optional]` instead of leaving it to the help text to say so, and the permission modes render as a block with a line of help each. `--seed ""` on `miniclaude mock` is a value now rather than a request for a random seed, so it is refused instead of silently ignored; omit the flag to get a random one.

### Features

- **`--new-session` names what used to be the absence of two other flags.** Which session `miniclaude repl` runs is now one selection over `--resume <id>`, `--continue-session` and `--new-session`; passing none of the three still starts a new session, so every command line that worked before works unchanged. Passing two is refused by name -- `--resume` and `--continue-session` are mutually exclusive -- and the refusal covers every pair rather than the one the code happened to check.
